# BATTLE EVENTS｜網站重建 Prompt

你是一位全端產品工程師。請開發名為 **BATTLE EVENTS** 的街舞賽事管理平台。交付可操作、可部署、可測試的完整應用，包含五個獨立入口、登入、後端 API 與共用雲端資料庫。下列內容是重建規格，請實作每項操作及其成功、失敗、無權限與資料衝突情境。

## 介面與入口

使用繁體中文，適用於手機、平板、桌機與現場大螢幕。延續 BATTLE EVENTS 的視覺識別，以深炭色導覽、橘色主操作、淺灰背景、白色卡片和幾何街舞海報呈現。桌面使用側邊導覽，窄螢幕收合選單。把當前活動、組別、流程階段與下一步放在操作區上方。狀態搭配文字，重要操作使用頁面內確認視窗。提供載入中、儲存中、已儲存、同步失敗及可採取的下一步。

| 路徑 | 入口 | 使用對象 |
|---|---|---|
| `/`、`/events` | 活動瀏覽與報名 | 舞者、訪客 |
| `/checkin` | 現場報到 | 活動擁有者、主辦管理員、指定報到人員 |
| `/judging` | 評審評分與 Battle 投票 | 已指派到組別的評審 |
| `/live` | Battle 現場公布 | 觀眾、主持人、大螢幕 |
| `/admin` | 後臺管理 | 活動擁有者、主辦管理員 |

## 1. 活動瀏覽與報名

- 支援關鍵字搜尋、城市與舞風篩選。詳情顯示日期時間、場地、組別、費用、規則、評審、DJ、MC 與報名狀態。
- 參賽者資料只要求舞名與手機號碼，並至少勾選一個組別。一次可報名多組。標準化台灣手機號碼，防止同活動同手機重複報名。
- 成功後顯示報名編號及 QR Code。QR Code 使用不透明查詢代碼。相同請求重試回傳原本的報名結果。已截止或組別不可報名時，由後端拒絕並顯示原因。

## 2. 現場報到

- 先選活動與組別，再掃描 QR Code，或用舞名、手機、報名編號查詢。相機拒絕授權或瀏覽器不支援掃描時，提供手動搜尋。
- 各組獨立記錄繳費及報到狀態與時間。顯示總報名、已報到、未報到、已繳費、未繳費。取消需填原因並確認，已有該舞者評分或晉級鎖定時拒絕取消報到。繳費功能只做狀態紀錄。
- 加入 **「結束報到」**，由活動擁有者或主辦管理員對當前組別操作。確認前顯示組別、已報到及未報到人數。確認後顯示「本組報到已結束」及結束時間，記錄操作者，凍結該組的新增及取消報到。其他組別、繳費狀態與原有評分流程各自運作。
- **「重新開放報到」** 需填原因並確認，僅在該組沒有評分、晉級鎖定或 Battle 賽程時允許。重新開放後可繼續報到。結束與重開都寫入操作紀錄。

## 3. 海選評分與 Battle 投票

- 評審使用自己的帳號，只能進入被指派的活動與組別。海選名單只列本組已報到舞者，只顯示本人分數及評語。
- 採用「名單＋評分卡」，顯示當前舞者、報名編號、待評／已評／全部篩選及完成進度。手機版讓評分和儲存按鈕容易觸及。
- 支援 0–100 分、最多兩位小數、選填評語及快速加減分。以舞者為單位保留頁面內未送出的草稿，明確區分草稿與雲端已儲存資料。捨棄草稿前確認。寫入成功後自動切換到下一位待評者。全部完成時顯示完成狀態，並提供回看已評名單。
- 修改既有分數須填原因，保存舊分數、評語、時間及原因。晉級鎖定後停止改分。跨裝置更新造成衝突時提示重新同步，保留尚未提交的輸入供核對。
- Battle 階段只開放目前場次投票，評審只能從該場兩位舞者選擇一人。每位評審在場次確認前可更新自己的票。主辦可查看票況並確認勝方。

## 4. Battle 現場公布

- 顯示已公布的晉級名單、對戰表、目前場次、已確認勝方與冠軍。提供列表、淘汰賽樹狀圖、全螢幕與定期自動更新。
- 樹狀圖連接各輪對戰，保留「待晉級」位置。窄螢幕允許水平捲動。
- 使用主辦確認時寫入的公開快照。後臺有變更時，等主辦重新確認並公布才更新公開畫面。暫停公布後顯示等待狀態。公開 API 以欄位白名單隔離手機、繳費、私人評語、登入帳號、內部操作紀錄與未公布結果。

## 5. 後臺管理與權限

- 建立與編輯活動，管理報名開關、組別、費用、評審、DJ、MC。顯示報名、繳費、報到、評審完成進度及各組目前階段。
- 權限以活動為範圍。用 Email 邀請主辦管理員、報到人員、評審，由對方登入並接受。支援指定組別、授權起訖時間、待接受／有效／撤銷狀態，異動及撤銷需留下原因與紀錄。擁有者負責管理主辦管理員、移轉所有權、匯出完整備份及還原。
- 報到人員只能在授權組別查詢及管理報到、繳費。評審只能在被指派組別看可評分名單、修改自己的分數及投票。主辦管理員可操作賽程與公布。所有 API 驗證身分、角色、活動、組別及資料歸屬。
- 每組設定 2、4、8、16 或 32 個晉級名額。以指定評審平均分排序。沒有指派評審、報到人數不足、漏評或晉級截止線同分時，阻止鎖定並指出原因。截止線同分須先加賽，再由原評審記錄結果及修正原因，或使用賽前已明訂並實作的判定規則。
- 鎖定晉級後，將合格舞者隨機配對並保存。重新整理或重複送出時沿用保存結果。主辦確認每場勝方後才能建立下一輪，決賽確認後產生冠軍並停止建輪。
- 修正已確認勝方須填原因並記錄異動。後續輪次已建立時拒絕直接覆寫。公布前提供核對，並提供「確認並公布」及「暫停公布」。
- 提供完整活動備份匯出、檔案驗證、還原預覽及確認。還原限同一活動、同一擁有者且尚未鎖定晉級或建立賽程，保留現有團隊權限及稽核紀錄。若需沿用舊系統，另提供保留原始資料的遷移預覽與確認流程。

## 資料、API 與可靠性

- 可採用現站的 React／Vinext、Cloudflare Workers、D1 與 ChatGPT 登入，也可採用具有等效能力的技術。身分由可信的伺服器端登入機制提供。密鑰只放在部署環境的伺服器設定。
- 資料至少涵蓋活動、組別、授權與邀請、報名及各組參賽狀態、評分與歷程、投票、對戰輪次、公布快照及操作紀錄。正式資料以雲端資料庫為準。
- 以交易或版本條件寫入確保跨裝置一致性，舊版本寫入回應衝突並提示重新同步。防止重複送出、拒絕無效輸入，對公開報名加入速率限制。真正寫入成功後才顯示儲存成功。若寫入成功但畫面未同步，分開提示兩個結果。
- 測試資料全部使用合成資料，標題明確加上「【範例】」。提供可重複執行且不會複製既有資料的產生功能，建立「24 位舞者報到演練」、「海選正常／截止線同分／漏評」與「8 強 Battle 現場」三種情境。

## 驗收與交付

1. 走完建立活動、開放報名、多組報名、分組繳費與報到、結束報到、海選評分、鎖定晉級、隨機配對、公布、評審投票、主辦確認勝方、逐輪晉級與公布冠軍。
2. 驗證未登入、錯誤角色、未被指派的組別、不同主辦及撤銷授權後皆無法取得或修改受保護資料。
3. 驗證結束報到只影響選定組別，繳費仍可操作。有評分後無法重開。驗證晉級漏評、人數不足、截止線同分、鎖定後改分及後續輪次已建立時的勝方更正。
4. 用兩個工作階段驗證跨裝置更新、舊版本寫入衝突、重複報名、請求重試、儲存失敗、首輪配對持久性及公開快照的隱私範圍。
5. 交付可部署原始碼、資料庫遷移、範例資料、啟動及部署說明、已執行的測試結果、部署環境所需設定及尚未完成的限制。分開報告模擬測試與實際裝置、多人或正式部署驗證。
